# Production deployment: what changed

The VPS (k3s, 2 vCPU / 8 GB) runs the **same Helm charts** as the laptop (k3d).
Nothing is forked or patched: every difference is a values file,
`deploy/<chart>-values-local.yaml` vs `deploy/<chart>-values-prod.yaml`.
Step-by-step install: `docs/deploy-vps.md`.

`BASE` = `2001-41d0-303-2774--94.sslip.io` (sslip.io resolves the IP written in the
name, so no DNS registrar or records are needed).

| Area | Chart | Value | Local (k3d) | VPS (k3s) |
|---|---|---|---|---|
| Domain | gateway | `ingress.host` | `gateway.localhost` | `gateway.BASE` |
| Domain | dashboard | `ingress.host` | `dash.localhost` | `dash.BASE` |
| Domain | gateway, store-operator | `baseDomain` | `localhost` | `BASE` (stores `<name>.BASE`, edges `<slug>.gw.BASE`) |
| Ingress / https | gateway, store-operator | `urlScheme` | `http` | `https` |
| Ingress / https | gateway | `cookieSecure` | `false` | `true` (session cookie https-only) |
| TLS | store-operator | `clusterIssuer` | none | `letsencrypt` (each store/edge Ingress gets its own certificate) |
| Storage | postgres | `persistence.size` | `1Gi` | `5Gi` |
| Capacity | gateway / store-operator | `stores.maxPerAdmin` / `maxStores` | `3` (default) | `10` |
| Reach over IPv4 | gateway / dashboard | `tailnetDomain` / `tailscale.hostname` | off | Tailscale Funnel names (the VPS is IPv6-only inbound) |

**Ingress.** Both clusters use the Traefik that k3s/k3d ship; no controller to install.

**TLS (cert-manager).** `deploy/tls-prod.yaml`, applied once:
a `letsencrypt` ClusterIssuer (HTTP-01 through Traefik, so no DNS API token),
one certificate for `dash` and `gateway` served as Traefik's default, and an
http→https redirect for every host. cert-manager renews 30 days before expiry.
Locally everything is plain http.

**Storage.** Both use the built-in `local-path` StorageClass; on the VPS the
volumes live on its disk under `/var/lib/rancher/k3s/storage`. Each store
namespace is capped by a ResourceQuota (2 PVCs, 3Gi).

**Secrets.** No secret is in any values file or in git. They are created on the
cluster with `kubectl create secret` and fresh random values (`docs/deploy-vps.md`
step 5); charts only name them (`dbSecret: gateway-db`, `existingSecret: gateway-admin`,
`credentialsSecret: gateway-credentials`). Same names and keys locally, different
values. Per-store Secrets are generated by the operator on both.

**Images.** Locally: chart-default tags, built and loaded with `k3d image import`.
VPS: `ghcr.io/shiv2576/<service>:<commit SHA>`, set in the `image:` block of each
`deploy/*-prod.yaml` (and `edgeImage*`/`wooMcpImage` for the operator) by CI. See `docs/gitops.md`.

**Check what a release really runs:** locally `helm get values <release> -n mercora`;
on the VPS the `deploy/*-prod.yaml` at `main` (Argo CD shows Synced when they match).
`helm get values` there is stale for Argo-managed releases (Argo applies without Helm).
